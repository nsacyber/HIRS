# Security Policy

## Reporting a security vulnerability

If you believe you have found a security vulnerability, use the repository's
**Security** tab and select **Report a vulnerability** to submit a private
report. Please do not disclose a potential vulnerability in a public issue,
pull request, or organization-wide email.

Include the affected component and version, what you observed, steps to
reproduce, and the potential impact. Distinguish confirmed behavior from
assumptions or possible consequences. Please describe the impact accurately
rather than assigning a severity based on an unverified scenario.

## Other requests

For feature requests, questions, and bugs that do not expose a security
vulnerability, open a regular GitHub issue. If you are unsure whether
a finding is security-sensitive, use private reporting rather than posting
potentially sensitive details publicly.

## Before submitting

Please have a person review the submission, check the relevant documentation
and behavior, and choose the reporting route that best fits the finding. By
submitting, you confirm that a person has reviewed it and that you have made
a good-faith effort to verify and classify it appropriately.

We review actionable security reports, but cannot guarantee an individual
response to every submission. Reports without enough detail to investigate
may be closed or left unanswered.
